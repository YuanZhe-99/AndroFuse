# Wire & Core Protocols (M1a–M1b)

AndroFuse implements direct wire-protocol engines in Rust (`core/androfuse-core`) and Go (`internal/adb`, `internal/scrcpy`, `internal/dex`, `internal/lease`) without shelling out to `scrcpy.exe`.

## 1. `scrcpy-server v5.0.1` Wire Protocol

`tools/fetchdeps` downloads upstream `scrcpy-server-v5.0.1` (Apache-2.0, pinned SHA-256 `764eb6f79811d5211fe9df341120882ba9994c7a61b897d7bf3fb662e53bc536`) into `.dev/cache/`. Sessions push it to `/data/local/tmp/androfuse-scrcpy-server.jar` and connect over `adb forward tcp:<port> localabstract:scrcpy_<scid>` across USB ADB, TLS Wi-Fi ADB (`_adb-tls-connect._tcp`), or Android Emulator (`emulator-*`):

1. **Video & audio socket handshake**: optional `0x00` dummy byte (`tunnel_forward=true`) on the first socket, 64-byte NUL-padded UTF-8 device name + 4-byte big-endian video `codec_id` (`0x68323634` H.264, `0x68323635` H.265). When `audio=true audio_codec=raw` is enabled, the subsequent audio socket reads a 4-byte `codec_id` (`0x00726177` raw 48kHz stereo s16le PCM) and gracefully exits if the device emits `0x00000000` (disabled) or `0x00000001` (unsupported).
2. **12-byte packet header**:
   - **Session packet** (`byte[0] & 0x80 != 0`): `client_resized = (byte[3] & 1) != 0`, `width = BE u32(4..8)`, `height = BE u32(8..12)`.
   - **Media packet** (`byte[0] & 0x80 == 0`): `is_config` (bit 62), `is_keyframe` (bit 61), `pts_us` (lower 61 bits), `size = BE u32(8..12)`. Cached CSD config packets are prepended to keyframes automatically and passed to `MP4Recorder` when recording.
3. **Interactive control, chromeless app windows, & CLI rules**:
   - Never pass `start_app` or `mouse=uhid` on the `com.genymobile.scrcpy.Server` CLI, and never pass both `display_id` and `new_display`.
   - Independent App Windows launch with 16px-aligned dimensions (`640x1120/220`, dynamically scaled at `1.5x` on resize), `flex_display=true`, `vd_system_decorations=false`, and `TYPE_START_APP` (`+pkg`) for pure chromeless rendering without Android status/nav bars.
   - Desktop interaction routes directly per window (`INV-12`) via `TYPE_INJECT_TOUCH_EVENT` (`2`, supporting both `PointerIDMouse = -1` and `PointerIDGenericFinger = -2`), `TYPE_INJECT_SCROLL_EVENT` (`3`, fixed-point `i16`), `TYPE_INJECT_KEYCODE` (`0`), `TYPE_INJECT_TEXT` (`1`), `TYPE_SET_CLIPBOARD` (`9`, plus device→PC clipboard callbacks), `TYPE_SET_DISPLAY_POWER` (`10`), `TYPE_ROTATE_DEVICE` (`11`), `TYPE_UHID_*` (`12–14`), `TYPE_START_APP` (`16`), and `TYPE_RESIZE_DISPLAY` (`21`).

## 2. Samsung Native DeX Loopback & App Icon Extraction (`server/dexhelper`)

`tools/builddex` compiles `server/dexhelper/src/com/androfuse/dexhelper/Main.java` into `build/androfuse-dex-helper.jar` (`--min-api 30`, zero Root, UID 2000 `shell`).

- **`probe`**: Bootstraps `Looper` + `ActivityThread` (`com.android.shell`) workarounds and reflects `SemWifiDisplayConfig$Builder` and `IDisplayManager.connectWifiDisplayWithConfig`, emitting `AFDEX1|PROBE|{json}`.
- **`apps [--no-icons]`**: Bootstraps `ActivityThread.systemMain()` system context, queries `ACTION_MAIN` / `CATEGORY_LAUNCHER` via `PackageManager`, filters WebAPK/hex-hash noise, reads localized labels and `resizeMode`, renders `96x96` ARGB_8888 PNG icons, and emits `AFDEX1|APP|{json}` + `AFDEX1|APPS_DONE|<count>`.
- **`serve <token> <w> <h> <dpi> <grace_sec>`**: Wakes the display (`KEYCODE_WAKEUP`), acquires `/data/local/tmp/androfuse-dex.lock`, invokes `disconnectWifiDisplay()`, binds loopback UDP drain ports plus a loopback TCP control listener (`127.0.0.1:<ctrlPort>`, advertised as the optional 8th field in `AFDEX1|<token>|READY|<id>|<w>|<h>|<dpi>|<type>|<flags>|<pid>|<ctrlPort>`), calls `connectWifiDisplayWithConfig` (`127.0.0.1:7236`, `"AndroFuseDeX"`, `mode=2`), drives the WFD RTSP `OPTIONS` → `GET_PARAMETER` → `SET_PARAMETER` → `SETUP` → `PLAY` state machine, enforces the **initial DPI ≥ 160 bootstrap rule** (`wm size` + `wm density`), supports live `RESIZE <w> <h> <dpi>`, holds the display alive during a `grace_sec` window (`AFDEX1|<token>|GRACE|<grace_sec>`) on unexpected stdin EOF, and tears down cleanly on `STOP` or grace expiry. The PC launches `serve` detached (`setsid -w nohup`; a plain launch where toybox lacks `setsid -w`): adbd kills the shell's process group when its transport drops (USB unplug, Wi-Fi loss), which used to kill the helper before its grace window could start.
- **`attach <token> <ctrl_port>`**: Attaches to a surviving `serve` instance over `127.0.0.1:<ctrl_port>` during USB→TLS Wi-Fi handoff (`INV-02`), authenticates with `AUTH <token>`, receives `AFDEX1|<token>|REATTACHED|<id>|<w>|<h>|<dpi>`, and bridges `PING` / `RESIZE` / `STOP` seamlessly.
- **`SelectRoute` & `EvaluateTruth` (`INV-06`)**: One UI 9.0 (`SDK 37`) merges DeX into SystemUI/Launcher (no `com.sec.android.app.desktoplauncher` package), so `internal/dex` validates Samsung OEM identity + active `SemWifiDisplayConfig` display ownership rather than the legacy package name and allows manual switching between Native DeX and clearly labeled Virtual Display Fallback.

## 3. Miracast / Wi-Fi Direct Sink (`core/androfuse-core/src/miracast.rs` — Hidden / Shelved)

- **Why Hidden Across All Platforms**: Third-party Windows Miracast Sink advertisement cannot be accomplished through public WinRT APIs alone — it requires invoking Microsoft's undocumented private `wlanapi.dll!WlanNotifyVsIeProviderInt` interface (`GUID b7d94b4d-5db1-4e70-b5c3-dd003eeebe66`). Live verification on Windows 11 ARM64 (`build 26300`, Qualcomm WCN685x WiFiCx `qcwlan8280.sys` `1.0.4122.4000`) proved that peer Miracast association against a `WlanNotifyVsIeProviderInt` GO Sink triggers a kernel-mode `BugCheck 0x0000007E` (`0xC0000005`) inside `qcwlan8280.sys`. Because AndroFuse refuses to ship features backed by unstable undocumented OS internals, the Miracast Sink entry is hidden in the UI and disabled at runtime across all architectures; wired USB ADB and **encrypted TLS Wi-Fi ADB (`_adb-tls-connect._tcp`)** serve as the supported DeX transports.
- **Preserved Offline Protocol Stack**: The pure-Rust WFD RTSP (`OPTIONS` → `GET_PARAMETER` → `SET_PARAMETER` → `SETUP` → `PLAY`), RTP reorder, MPEG-TS H.264 demuxer, and UIBC packet codecs remain unit-tested in `miracast.rs` as reference code without touching WLAN drivers.

## 4. C-ABI v6 NV12 / WASAPI Pipeline, Local IPC & Lease Ledger (`leases.json`)

| Component | Contract |

## 5. Offline Fixtures & Live Device Suite

- Offline tests replay sanitized 64×48 H.264 packets (`internal/scrcpy/testdata/fold8_scrcpy_session.json`) over loopback TCP through Media Foundation NV12 → `ui.Bitmap.UpdateYUV` (`ui.NewTester`), containing zero phone screen imagery or serials.
- Live device validation (`Spikes S1, S2, S4`) is guarded behind `$env:ANDROFUSE_LIVE_DEVICE = "1"` in `internal/scrcpy` and `internal/dex` and verifies clean display/forward teardown automatically.

## 6. Optional Android Companion TLS 1.3 Protocol (`internal/companion`)

- **Authenticated Transport (`INV-07`)**: `internal/androidhost` hosts an optional ECDSA P-256 TLS 1.3 server on two listeners: TCP on all interfaces at a random high port in 20000–48999 (`companion.PickPort`, saved in `companion.json` and kept while it stays free, so a paired computer's LAN or mesh address keeps working; the Companion screen shows it), and the abstract local socket `@androfuse-companion` that the computer reaches with `adb forward tcp:0 localabstract:androfuse-companion`, so pairing over adb needs no fixed port. Its SHA-256 certificate fingerprint is pinned by callers; every connection must authenticate its first `auth` frame via constant-time pairing token check (`subtle.ConstantTimeCompare`).
- **Graded Opt-In Permissions & Cross-Network ADB Beacon (`INV-09`, `INV-11`)**: `status.get`, `clipboard.set`, `notification.reply`, `app.continuity`, `file.push` (traversal-rejected + SHA-256 verified), `display.guard`, and dynamic `_adb-tls-connect._tcp` port advertisement are gated individually on user switches inside Android Companion, while base USB/Wi-Fi mirroring and DeX remain 100% functional without any APK installed.
- **First pairing over adb (numeric comparison, `INV-09`)**: the computer installs the Companion with `adb install -r`, opens it with the secret-free `androfuse://pair` link (which only starts the Companion service), `adb forward`s the Companion's local socket and sends `pair.request {client_name, code}`. The Companion accepts that frame **only on the local socket or a loopback connection** (LAN devices cannot raise prompts), shows the computer's name and the 6-digit code, and returns `{token, cert_fingerprint}` only after the user taps Allow; Decline or `PairWait` (60 s) fails it. The computer checks the TLS fingerprint and then connects normally with the token.
- **Mesh hand-over (`mesh.join`, `INV-07`, `INV-08`)**: sent only when the computer's user ticked "Also join the mesh" and the computer's mesh is running: `{network_name, network_secret, peers}`, where `peers` are the computer's relays plus its listeners with a wildcard host replaced by its LAN IPv4 addresses. The phone seals the secret with an Android Keystore AES-GCM key, joins with no TUN and no listener, rejoins whenever the Companion service starts, and can leave at any time. When the computer lets other devices connect directly, it listens on a random high port in 20000–48999 that is free for both TCP and UDP (below the Windows dynamic range, skipping ports in use or reserved), and keeps it while it stays free. EasyTier's own errors (for example a listener port already in use) come back in `mesh.status` `error`, and the instance is then not reported as running.
- **Reconnecting without adb and low power**: `pair.res` also carries the Companion's TCP `port` and its `model`, the name it joins the mesh under. The computer keeps both with the pinned fingerprint and the DPAPI-sealed token in `devices.json`; later it reconnects through adb's local socket while the phone is on adb, otherwise it looks up the phone's mesh IPv4 in EasyTier's routes by that name (`Manager.PeerIPv4`) and adds a `127.0.0.1` port forward to it (`INV-07`). The phone runs the mesh in low-power mode unless its user turns Save battery off: `mesh.start` `low_power` sets EasyTier's `multi_thread = false`, `lazy_p2p`, `disable_upnp` and `disable_sym_hole_punching`.
- **Several networks (V3)**: the desktop keeps up to 8 EasyTier networks in `gui.json` (`MeshPrefs.Networks`: the name shown here, network name, servers, DPAPI-sealed secret, Join, and a random high port per network for direct connections) and runs one core instance per joined network (`mesh.start` `instance`, a name of 1–32 letters, digits, `-` or `_`; `mesh.stop` / `mesh.status` take the same `instance`, and `mesh.stop` without one stops them all). Settings › Network's Advanced choices map to `disable_p2p` (Try direct connections off) and `latency_first`. The desktop reads each running instance every 3 s for its mesh address, UDP NAT type and peers (EasyTier's `peer_route_pairs`: hostname, address, direct when a direct connection exists, latency from the connection's `latency_us` or the route's `path_latency`). EasyTier binds outbound peer sockets to physical interfaces, so a peer on the same machine is reached on the LAN address, not `127.0.0.1`.
- **Wireless debugging through the Companion (`tunnel.open`, `INV-07`)**: on a new authenticated connection the desktop sends `tunnel.open {port}`; the phone accepts only its own Wireless debugging port (the one it found with NsdManager and saved), and only once `127.0.0.1:<port>` answers the CNXN handshake with STLS; after `tunnel.res` the connection is a byte pipe to that port until either side closes. The desktop listens on a free loopback port and opens one tunnel per accepted connection (`companion.ServeTunnels`), so `adb connect 127.0.0.1:<port>` reaches the phone's Wireless debugging through its Companion on the LAN or across a network (through one mesh forward to the Companion's port). Needs the phone's "Wireless debugging through the Companion" permission (off by default).
- **The Wireless debugging port is found, not typed**: the Companion discovers `_adb-tls-connect._tcp` with Android's NsdManager, keeps the advertisement whose address is one of the phone's own, checks the port with the CNXN probe and reports it in `status.get`; when the advertisement goes away (Wireless debugging off, or no Wi-Fi) it reports 0.
- **Screen sharing on mobile data (`share.open`, `input.key`, `INV-09`)**: Wireless debugging runs only on Wi-Fi, so on mobile data the desktop can ask the Companion to share its screen. `share.open` makes the phone show Android's MediaProjection consent; once allowed, a `mediaProjection` foreground service (with a Stop notification) encodes the screen with MediaCodec H.264 (at most 1280 pixels on its longest side, 30 fps, 4 Mbit/s) into scrcpy-server's video framing on the abstract socket `androfuse-share`, and the reply turns the connection into that stream, which the desktop decodes with `scrcpy.StartFromConns`. `input.key {action}` runs `back`, `home` or `recents` through the Companion's accessibility service (declared without capabilities, because MyGo plugins cannot ship its XML, so it performs global actions only, after the user turns it on). Both need the phone's "Share the screen on mobile data" permission (off by default); taps, typing and sound are not available this way.
- **Connecting with only an address**: Home's "Connect a phone" takes an IP address, a domain or a phone's name. With a port it connects to it; without one the desktop tries the phone's remembered Wireless debugging address, then its Companion (tunnel), then, for an address it can route to directly, searches ports 30000–60999 with TCP connects and the CNXN probe (`adb.FindWirelessPort`, several hundred at a time, about twenty seconds, cancellable). A port that answers STLS but refuses this computer asks for the pairing code and pairing port the phone shows (`adb pair`). A mesh peer's address is reached only through its Companion, since the desktop has no virtual adapter. Only when everything fails does the card ask for the port shown on the phone.

## 7. Opt-In Local MCP Control Interface (`internal/mcp`)

- **Default-Disabled Loopback Binding (`INV-07`, `INV-08`)**: Starts disabled (`Enabled=false`). Explicit activation from Settings binds strictly to `127.0.0.1:0` over HTTP (`POST`) with a fresh 32-char random bearer token checked via `subtle.ConstantTimeCompare` and a bounded 30-minute TTL.
- **Allowlist, Emergency Stop & Scrubbed Audit**: `tools/list` and `tools/call` enforce per-tool `Allowlist` flags (`list_devices` and `run_diagnostics` allowed by default when enabled; `launch_app` requires an explicit Settings toggle). `EmergencyStop()` (also invoked automatically on app shutdown) clears tokens/listeners immediately, and audit entries never log bearer tokens or raw device serials. Since V3 the desktop also passes `Handlers.Approve`: `tools/list` then lists every tool, the allowlist names the ones that run without asking (Settings › Security and privacy), and each other call shows a card above the panes (and a notification) and waits up to two minutes for Allow once or Deny; the answer is audited (`approval`, `user_allowed_once` or `user_denied`).

## 8. Bidirectional Camera & Mic Bridge (`internal/avbridge`, `M5`)

- **Phone Camera + Mic Capture**: `internal/scrcpy` supports `video_source=camera` (`camera_facing`, `camera_size`, `camera_fps`, `control=false`) alongside `audio_source=mic` into a desktop `SessionWindow` and a loopback-only (`127.0.0.1`) token-gated MJPEG HTTP server (`avbridge.MJPEGServer`) that skips JPEG encoding whenever no local client is connected; Windows `MFCreateVirtualCamera` API presence is probed honestly (`ProbeVirtualCamera`) while noting no standalone COM media-source driver is installed.
- **Non-Root PC-to-Android Uplink (`INV-09`)**: `av.push` on `internal/companion` carries bounded (`<= 2 MiB`) `mic_pcm` / `camera_jpeg` frames over TLS 1.3 only when the `MediaBridge` permission switch is explicitly enabled in Android Companion.

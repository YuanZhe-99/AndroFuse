# Wire & Core Protocols (M1a–M1b)

AndroFuse implements direct wire-protocol engines in Rust (`core/androfuse-core`) and Go (`internal/adb`, `internal/scrcpy`, `internal/dex`, `internal/lease`) without shelling out to `scrcpy.exe`.

## 1. `scrcpy-server v5.0.1` Wire Protocol

`tools/fetchdeps` downloads upstream `scrcpy-server-v5.0.1` (Apache-2.0, pinned SHA-256 `764eb6f79811d5211fe9df341120882ba9994c7a61b897d7bf3fb662e53bc536`) into `.dev/cache/`. Sessions push it to `/data/local/tmp/androfuse-scrcpy-server.jar` and connect over `adb forward tcp:<port> localabstract:scrcpy_<scid>` across USB ADB, TLS Wi-Fi ADB (`_adb-tls-connect._tcp`), or Android Emulator (`emulator-*`):

1. **Video & audio socket handshake**: optional `0x00` dummy byte (`tunnel_forward=true`) on the first socket, 64-byte NUL-padded UTF-8 device name + 4-byte big-endian video `codec_id` (`0x68323634` H.264, `0x68323635` H.265). When `audio=true audio_codec=raw` is enabled, the subsequent audio socket reads a 4-byte `codec_id` (`0x00726177` raw 48kHz stereo s16le PCM) and gracefully exits if the device emits `0x00000000` (disabled) or `0x00000001` (unsupported).
2. **12-byte packet header**:
   - **Session packet** (`byte[0] & 0x80 != 0`): `client_resized = (byte[3] & 1) != 0`, `width = BE u32(4..8)`, `height = BE u32(8..12)`.
   - **Media packet** (`byte[0] & 0x80 == 0`): `is_config` (bit 62), `is_keyframe` (bit 61), `pts_us` (lower 61 bits), `size = BE u32(8..12)`. Cached CSD config packets are prepended to keyframes automatically and passed to `MP4Recorder` when recording.
3. **Interactive control, chromeless app windows, & CLI rules**:
   - Never pass `start_app` or `mouse=uhid` on the `com.genymobile.scrcpy.Server` CLI, and never pass both `display_id` and `new_display`.
   - Independent App Windows launch with 16px-aligned dimensions (`640x1120/220`, dynamically scaled at `1.5x` on resize), `flex_display=true`, `vd_system_decorations=false`, and `TYPE_START_APP` (`+pkg`) for pure chromeless rendering without Android status/nav bars.
   - Desktop interaction routes directly per window (`INV-12`) via `TYPE_INJECT_TOUCH_EVENT` (`2`, supporting both `PointerIDMouse = -1` and `PointerIDGenericFinger = -2`), `TYPE_INJECT_SCROLL_EVENT` (`3`, fixed-point `i16`), `TYPE_INJECT_KEYCODE` (`0`), `TYPE_INJECT_TEXT` (`1`), `TYPE_SET_CLIPBOARD` (`9`, plus device→PC clipboard callbacks), `TYPE_SET_DISPLAY_POWER` (`10`), `TYPE_ROTATE_DEVICE` (`11`), `TYPE_UHID_*` (`12–14`), `TYPE_START_APP` (`16`), and `TYPE_RESIZE_DISPLAY` (`21`).

## 2. Samsung Native DeX Loopback & App Icon Extraction (`server/dexhelper`)

`tools/builddex` compiles `server/dexhelper/src/com/androfuse/dexhelper/Main.java` into `build/androfuse-dex-helper.jar` (`--min-api 30`, zero Root, UID 2000 `shell`).

- **`probe`**: Bootstraps `Looper` + `ActivityThread` (`com.android.shell`) workarounds and reflects `SemWifiDisplayConfig$Builder` and `IDisplayManager.connectWifiDisplayWithConfig`, emitting `AFDEX1|PROBE|{json}`.
- **`apps [--no-icons] [--resume <package>]`**: Bootstraps `ActivityThread.systemMain()` system context, queries `ACTION_MAIN` / `CATEGORY_LAUNCHER` via `PackageManager`, filters WebAPK/hex-hash noise, reads localized labels and `resizeMode`, renders `96x96` ARGB_8888 PNG icons, and emits `AFDEX1|APP|{json}` + `AFDEX1|APPS_DONE|<count>`. Icons come from the app's own icon resource first and from `PackageManager.loadIcon` only after that, because on One UI `loadIcon` runs an app's "live icon" code (Calendar, Clock), which fails under the shell uid or aborts `app_process` natively. Before drawing each icon the helper prints `AFDEX1|ICON|<package>`; if the process dies there, the computer keeps the apps it got and runs `apps --resume <package>` (at most three times), which lists that app without an icon and goes on after it. On a Galaxy Z Fold8 (One UI 9) all 158 apps come back with icons in 1.9 s.
- **`serve <token> <w> <h> <dpi> <grace_sec>`**: Wakes the display (`KEYCODE_WAKEUP`), acquires `/data/local/tmp/androfuse-dex.lock`, invokes `disconnectWifiDisplay()`, binds loopback UDP drain ports plus a loopback TCP control listener (`127.0.0.1:<ctrlPort>`, advertised as the optional 8th field in `AFDEX1|<token>|READY|<id>|<w>|<h>|<dpi>|<type>|<flags>|<pid>|<ctrlPort>`), calls `connectWifiDisplayWithConfig` (`127.0.0.1:7236`, `"AndroFuseDeX"`, `mode=2`), drives the WFD RTSP `OPTIONS` → `GET_PARAMETER` → `SET_PARAMETER` → `SETUP` → `PLAY` state machine, enforces the **initial DPI ≥ 160 bootstrap rule** (`wm size` + `wm density`), supports live `RESIZE <w> <h> <dpi>`, holds the display alive during a `grace_sec` window (`AFDEX1|<token>|GRACE|<grace_sec>`) on unexpected stdin EOF, and tears down cleanly on `STOP` or grace expiry. The PC launches `serve` detached (`setsid -w nohup`; a plain launch where toybox lacks `setsid -w`): adbd kills the shell's process group when its transport drops (USB unplug, Wi-Fi loss), which used to kill the helper before its grace window could start.
- **`attach <token> <ctrl_port>`**: Attaches to a surviving `serve` instance over `127.0.0.1:<ctrl_port>` during USB→TLS Wi-Fi handoff (`INV-02`), authenticates with `AUTH <token>`, receives `AFDEX1|<token>|REATTACHED|<id>|<w>|<h>|<dpi>`, and bridges `PING` / `RESIZE` / `STOP` seamlessly.
- **`SelectRoute` & `EvaluateTruth` (`INV-06`)**: One UI 9.0 (`SDK 37`) merges DeX into SystemUI/Launcher (no `com.sec.android.app.desktoplauncher` package), so `internal/dex` validates Samsung OEM identity + active `SemWifiDisplayConfig` display ownership rather than the legacy package name and allows manual switching between Native DeX and clearly labeled Virtual Display Fallback.

## 3. Miracast / Wi-Fi Direct Sink (`core/androfuse-core/src/miracast.rs` — Hidden / Shelved)

- **Why Hidden Across All Platforms**: Third-party Windows Miracast Sink advertisement cannot be accomplished through public WinRT APIs alone — it requires invoking Microsoft's undocumented private `wlanapi.dll!WlanNotifyVsIeProviderInt` interface (`GUID b7d94b4d-5db1-4e70-b5c3-dd003eeebe66`). Live verification on Windows 11 ARM64 (`build 26300`, Qualcomm WCN685x WiFiCx `qcwlan8280.sys` `1.0.4122.4000`) proved that peer Miracast association against a `WlanNotifyVsIeProviderInt` GO Sink triggers a kernel-mode `BugCheck 0x0000007E` (`0xC0000005`) inside `qcwlan8280.sys`. Because AndroFuse refuses to ship features backed by unstable undocumented OS internals, the Miracast Sink entry is hidden in the UI and disabled at runtime across all architectures; wired USB ADB and **encrypted TLS Wi-Fi ADB (`_adb-tls-connect._tcp`)** serve as the supported DeX transports.
- **Preserved Offline Protocol Stack**: The pure-Rust WFD RTSP (`OPTIONS` → `GET_PARAMETER` → `SET_PARAMETER` → `SETUP` → `PLAY`), RTP reorder, MPEG-TS H.264 demuxer, and UIBC packet codecs remain unit-tested in `miracast.rs` as reference code without touching WLAN drivers.

## 4. C-ABI v6 NV12 / WASAPI Pipeline, Local IPC & Lease Ledger (`leases.json`)

## 5. Offline Fixtures & Live Device Suite

- Offline tests replay sanitized 64×48 H.264 packets (`internal/scrcpy/testdata/fold8_scrcpy_session.json`) over loopback TCP through Media Foundation NV12 → `ui.Bitmap.UpdateYUV` (`ui.NewTester`), containing zero phone screen imagery or serials.
- Live device validation (`Spikes S1, S2, S4`) is guarded behind `$env:ANDROFUSE_LIVE_DEVICE = "1"` in `internal/scrcpy` and `internal/dex` and verifies clean display/forward teardown automatically.

## 6. Optional Android Companion TLS 1.3 Protocol (`internal/companion`)

- **Authenticated Transport (`INV-07`)**: `internal/androidhost` hosts an optional ECDSA P-256 TLS 1.3 server on two listeners: TCP on all interfaces at the first free one of four ports in 20000–48999 drawn from the phone's device id (`companion.DevicePorts`, SHA-256 of the id; `companion.PickDevicePort`, a random free port only when all four are taken; saved in `companion.json` and shown on the Companion screen). Different phones get different ports, and a computer that knows the id from the phone's mesh hostname finds the port again after the phone had to move off the saved one, where a purely random port was lost for good, and the abstract local socket `@androfuse-companion` that the computer reaches with `adb forward tcp:0 localabstract:androfuse-companion`, so pairing over adb needs no fixed port. Its certificate is drawn once and kept sealed with the Android Keystore (`identity.sealed`, `companion.MarshalIdentity`), so the SHA-256 fingerprint a computer pinned at pairing still matches after the Companion restarts, updates or the phone reboots (a certificate drawn per start broke every reconnection without adb); a computer that meets another certificate (`companion.ErrFingerprint`) pairs again the next time the phone is on adb. The fingerprint is pinned by callers; every connection must authenticate its first `auth` frame via constant-time pairing token check (`subtle.ConstantTimeCompare`).
- **Graded Opt-In Permissions & Cross-Network ADB Beacon (`INV-09`, `INV-11`)**: `status.get`, `clipboard.set`, `notification.reply`, `app.continuity`, `file.push` (traversal-rejected + SHA-256 verified), `display.guard`, and dynamic `_adb-tls-connect._tcp` port advertisement are gated individually on user switches inside Android Companion, while base USB/Wi-Fi mirroring and DeX remain 100% functional without any APK installed.
- **First pairing over adb or joined mesh (numeric comparison, `INV-09`)**: Over adb, the computer installs the Companion with `adb install -r`, opens it with `androfuse://pair`, `adb forward`s `@androfuse-companion`, and sends `pair.request {client_name, code}`. Across a joined EasyTier mesh (`PairMeshPhone`), the desktop sends `pair.request` through loopback forwards to the phone's `companion.DevicePorts(id)` even without desktop ADB (`PermDefaultsV2` enables `Telemetry`, `ADBBeacon`, and `ScreenShare` by default on fresh installs, and `Power.showPairNotification` posts an `IMPORTANCE_HIGH` heads-up notification). The Companion accepts `pair.request` **only on the local socket or a loopback connection** (LAN devices cannot raise prompts), displays the computer's name and the 6-digit code, and returns `{token, cert_fingerprint, device_name, manufacturer, brand, android_release, sdk_int, status}` once the user taps Allow. Desktop stores a mesh-paired phone under provisional `mesh:<devID>` in `devices.json` and merges it losslessly (alias, auto-reconnect, binding) into the real `HardwareHash` (`ro.serialno`) when ADB connects later. Forgetting a computer stops its token at once and leaves others paired; Decline or `PairWait` (60 s) fails it.
- **Mesh hand-over (`mesh.join`, `INV-07`, `INV-08`)**: sent only when the computer's user ticked "Also join the mesh" and the computer's mesh is running: `{network_name, network_secret, peers}`, where `peers` are the computer's relays plus its listeners with a wildcard host replaced by its LAN IPv4 addresses. The phone seals the secret with an Android Keystore AES-GCM key, joins with no TUN and no listener, rejoins whenever the Companion service starts, and can leave at any time. When the computer lets other devices connect directly, it listens on a random high port in 20000–48999 that is free for both TCP and UDP (below the Windows dynamic range, skipping ports in use or reserved), and keeps it while it stays free. EasyTier's own errors (for example a listener port already in use) come back in `mesh.status` `error`, and the instance is then not reported as running.
- **Reconnecting without adb and low power**: `pair.res` also carries the Companion's TCP `port`, its `model`, and `mesh_host`, the hostname it joins networks under (below); `auth.res` carries `mesh_host`, `device_name`, `manufacturer`, and `brand` too, and the computer updates saved metadata on every connection. The computer keeps both with the pinned fingerprint and the DPAPI-sealed token in `devices.json`; later it reconnects through adb's local socket while the phone is on adb, otherwise it looks up the phone's mesh IPv4 in EasyTier's routes by that hostname, matching the device id so a renamed phone is still found (`Manager.PeerIPv4`, `mesh.SameDevice`), adds `127.0.0.1` port forwards to its saved port and to the ports of `companion.DevicePorts(id)` in one restart of that network, connects through the first that answers and saves that port (`INV-07`). `status.get` also reports `mesh_network`, `mesh_running` (never the secret), `usb_debug_on`, `wireless_debug_on`, `wireless_adb_pair_port`, `adb_tunnel_allowed`, `screen_share_allowed`, and the battery from Android's `BatteryManager`. Each time a phone comes online over adb, the computer checks its Companion once (`syncCompanion`).
- **Several networks (V3)**: the desktop keeps up to 8 EasyTier networks in `gui.json` (`MeshPrefs.Networks`: the name shown here, network name, servers, DPAPI-sealed secret, Join, and a random high port per network for direct connections) and runs one core instance per joined network (`mesh.start` `instance`, a name of 1–32 letters, digits, `-` or `_`; `mesh.stop` / `mesh.status` take the same `instance`, and `mesh.stop` without one stops them all). Settings › Network's Advanced choices map to `disable_p2p` (Try direct connections off) and `latency_first`. The desktop reads each running instance every 3 s for its mesh address, UDP NAT type and peers. Every AndroFuse device joins as `AF-<p|c>-<id> <name>` (`mesh.Hostname`; `ParseHostname` also accepts earlier `AndroFuse-<phone|pc>-<id>`). The computer shows only peers with that prefix: Home discovers unpaired `phone` peers automatically under "Found nearby or in your networks" without exposing raw mesh IPs, and Settings › Network lists phones and computers.
- **Wireless debugging connect & pairing ports through the Companion (`tunnel.open`, `INV-07`)**: `tunnel.open {port}` accepts only the phone's verified Wireless debugging connect port (`_adb-tls-connect._tcp`) or active Wireless debugging pairing port (`_adb-tls-pairing._tcp`) once `127.0.0.1:<port>` answers STLS; after `tunnel.res` the connection is a byte pipe (`companion.ServeTunnels`). On first Wi-Fi setup or one-time Enhanced mode activation (`EnsureEnhancedAndRun` / `ActivatePairAndBootstrap`), the desktop can pair ADB either directly on LAN (`_adb-tls-pairing._tcp` / `WifiIPv4`) or via the tunneled pairing port, bootstrap `dex.StartDaemon`, and disconnect temporary wireless ADB when `ConnectionMode` is `companion_only`.
- **The Wireless debugging ports are found, not typed**: `Power.kt` discovers both `_adb-tls-connect._tcp` and `_adb-tls-pairing._tcp` with Android's NsdManager, filters to the phone's own addresses, checks ports, and reports `wireless_adb_port` and `wireless_adb_pair_port` in `status.get`.
- **Screen sharing on mobile data (`share.open`, `input.key`, `INV-09`)**: `share.open` starts MediaProjection + MediaCodec H.264 framing on `androfuse-share`; `input.key {action}` runs `back`, `home` or `recents` via AccessibilityService when enabled.
- **Guided adding & manual fallback (`wizard.go`)**: `+ Add a phone` guides USB cable, automatic Same Wi-Fi 6-digit pairing (`_adb-tls-pairing._tcp`), and Cross-network mesh pairing, keeping raw IP/port search (`adb.FindWirelessPort` 30000–60999) inside a collapsible Advanced section.

## 7. Opt-In Local MCP Control Interface (`internal/mcp`)

- **Default-Disabled Loopback Binding (`INV-07`, `INV-08`)**: Starts disabled (`Enabled=false`). Explicit activation from Settings binds strictly to `127.0.0.1:0` over HTTP (`POST`) with a fresh 32-char random bearer token checked via `subtle.ConstantTimeCompare` and a bounded 30-minute TTL.
- **Allowlist, Emergency Stop & Scrubbed Audit**: `tools/list` and `tools/call` enforce per-tool `Allowlist` flags (`list_devices` and `run_diagnostics` allowed by default when enabled; `launch_app` requires an explicit Settings toggle). `EmergencyStop()` (also invoked automatically on app shutdown) clears tokens/listeners immediately, and audit entries never log bearer tokens or raw device serials. Since V3 the desktop also passes `Handlers.Approve`: `tools/list` then lists every tool, the allowlist names the ones that run without asking (Settings › Security and privacy), and each other call shows a card above the panes (and a notification) and waits up to two minutes for Allow once or Deny; the answer is audited (`approval`, `user_allowed_once` or `user_denied`).

## 8. Bidirectional Camera & Mic Bridge (`internal/avbridge`, `M5`)

- **Phone Camera + Mic Capture**: `internal/scrcpy` supports `video_source=camera` (`camera_facing`, `camera_size`, `camera_fps`, `control=false`) alongside `audio_source=mic` into a desktop `SessionWindow` and a loopback-only (`127.0.0.1`) token-gated MJPEG HTTP server (`avbridge.MJPEGServer`) that skips JPEG encoding whenever no local client is connected; Windows `MFCreateVirtualCamera` API presence is probed honestly (`ProbeVirtualCamera`) while noting no standalone COM media-source driver is installed. A camera start that fails right away is tried twice more 1.5 s apart, because just after another camera session the phone may still hold the camera and its scrcpy-server then aborts. A camera pane starts muted (the phone's microphone is loud on the computer's speakers) and its header has Switch camera, a sound toggle, Screenshot and Fullscreen instead of the phone keys; scrcpy chooses the camera when it starts, so Switch camera keeps the same pane or window, its sound setting and its MJPEG bridge, shows the last picture under "Switching to the front camera…", closes the stream (letting go of the camera) and starts the other camera into the same session (`startCameraStream`).
- **Non-Root PC-to-Android Uplink (`INV-09`)**: `av.push` on `internal/companion` carries bounded (`<= 2 MiB`) `mic_pcm` / `camera_jpeg` frames over TLS 1.3 only when the `MediaBridge` permission switch is explicitly enabled in Android Companion.
- **Persistent UID 2000 Daemon Local IPC & Streams (v0.2.0 Phase 1–2 & Feature Parity)**: `dex.StartDaemon` pushes both `androfuse-dex-helper.jar` and `androfuse-scrcpy-server.jar` and starts `server/dexhelper` `daemon` detached under UID 2000 (`shell`). It acquires `/data/local/tmp/androfuse-daemon.lock`, pushes a scoped `IBinder` (`com.androfuse.daemon.IDaemon`) to `com.yuanzhe.androfuse.daemon` (`AndroFuseDaemonProvider`, `sendBinder`) via `IActivityManager.getContentProviderExternal` + `IContentProvider.call`, enforces `Binder.getCallingUid() == expectedAppUid`, probes `ADD_TRUSTED_DISPLAY`, verifies zero-copy `Os.socketpair` `ParcelFileDescriptor` transfers (`TX_ECHO_FD`), registers `linkToDeath`, and reports `daemon_ready`, `daemon_pid`, `daemon_trusted_display`, and `daemon_fd_verified` in `status.get`. For full mirroring, Samsung Native DeX, and Independent App Windows (`INV-01`) without Wireless debugging, `daemon.open` (`DaemonStreamRequest`, including optional `start_app`) and `daemon.ctrl` (`companion.DialDaemonStream`, with `3s` TCP keepalive and `TCP_NODELAY`) trigger `TX_OPEN_SESSION`, launching `scrcpy-server v5.0.1` (`cleanup=false` so the cached JAR survives across sessions while process exit / Binder death still releases virtual displays, `INV-03`) and bridging its video and control `LocalSocket`s over the transferred `Os.socketpair` FDs to Companion TLS 1.3. To prevent multi-megabyte video queue lag on slow links, `companionRoutes` prioritizes `adb forward` and direct Wi-Fi/LAN TCP (`WifiIPv4` / `Endpoint`) ahead of EasyTier mesh forwards, `companionStreamProfile` adapts bitrate/resolution/codec to the active path (`6–8 Mbps` up to `60 fps` on ADB/direct LAN, `2–2.5 Mbps` on WAN P2P, and `1–1.5 Mbps` / `30 fps` / `960`px or `1280×720` with H.265 when hardware-supported over relayed 5G links), and the video pipe caps socket buffers (`SO_SNDBUF`/`SO_RCVBUF` at `64 KB`) and pump buffers (`32 KB`) across `Daemon.java`, `Daemon.kt`, and `companion.Server` (`tuneVideoConn`). On desktop, `PairCompanionOverADB` and `syncCompanion` automatically bootstrap `dex.StartDaemon` over ADB whenever `daemon_ready` is false; `LaunchShare` checks `status.get` and opens full interactive mirroring via `DialDaemonStream` (Tier 2) when `daemon_ready` is true, falling back transparently to MediaProjection `DialShare` (Tier 3) when the daemon is unavailable; `LaunchDaemonDesktop` opens Native DeX (`dex:1920x1080/160` on Samsung, or `dex:1280x720/140` on relayed links) or `1920x1080/200` / `1280x720/160` `FlexDisplay`; `LaunchDaemonAppWindow` launches cached user apps (`icon-cache/<hwHash>/apps.json`) via `start_app` (`+pkg`) over `DialDaemonStream`. Settings › Phones and picture exposes `ConnectionMode` (`both_adb`, `both_companion`, `companion_only`) and `AutoSwitch` (fast Companion fallback on 5G drop + automatic upgrade back to healthy Wi-Fi/USB ADB in `both_adb`, paired with session status strip feedback and manual Reconnect). On Android, `Power.kt` restarts NSD discovery for `_adb-tls-connect._tcp` on Wi-Fi transitions and `status.get` reports complete phone telemetry (`app_version`, `app_build_hash`, `companion_port`, `standby_running`, `accessibility_on`, `wireless_adb_port`, `wifi_ipv4`, and `daemon_*`) so the desktop maintains live phone-card telemetry, updates mismatched Companion APKs or bootstraps Enhanced mode via ADB at least once when needed (even in `companion_only`, disconnecting the temporary wireless ADB session afterward), and discovers changed Wireless Debugging ports without relying solely on LAN multicast (backed by a rate-limited `adb.FindWirelessPort` fallback). For full Independent App Windows without ADB, `apps.list` (`TX_LIST_APPS`) queries launchable apps directly from the UID 2000 daemon (`dexhelper apps --no-icons`), reusing cached icon PNGs on disk.

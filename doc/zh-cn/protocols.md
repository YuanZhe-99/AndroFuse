# 线协议与核心引擎（M1a–M1b）

AndroFuse 在 Rust（`core/androfuse-core`）与 Go（`internal/adb`、`internal/scrcpy`、`internal/dex`、`internal/lease`）内直接实现协议引擎，不通过命令行派生 `scrcpy.exe`。

## 1. `scrcpy-server v5.0.1` 线协议

`tools/fetchdeps` 从上游拉取 `scrcpy-server-v5.0.1`（Apache-2.0，固定校验 SHA-256 `764eb6f79811d5211fe9df341120882ba9994c7a61b897d7bf3fb662e53bc536`）至 `.dev/cache/`；`scripts/build.sh` 将其随 Windows 安装包放在 `androfuse.exe` 旁（缺少它或 `bin/` 中的 `androfuse-dex-helper.jar` 时构建失败）。直接 ADB 会话把它推送到自己的副本 `/data/local/tmp/androfuse-scrcpy-session.jar`（`cleanup=true` 会让 scrcpy-server 退出时删除自己的 JAR，因此绝不能碰守护进程锁定的 `androfuse-scrcpy-server.jar`），并通过 `adb forward tcp:<port> localabstract:scrcpy_<scid>` 建连（支持 USB、TLS 无线 ADB `_adb-tls-connect._tcp` 与 Android 模拟器 `emulator-*`）：

1. **音视频 Socket 握手**：首个 Socket 读取可选 `0x00` 占位字节（`tunnel_forward=true`）、64 字节 NUL 填充 UTF-8 设备名与 4 字节大端视频 `codec_id`（`0x68323634` H.264、`0x68323635` H.265）。启用 `audio=true audio_codec=raw` 时，紧随其后的音频 Socket 读取 4 字节 `codec_id`（`0x00726177` 原始 48kHz 双声道 s16le PCM），若设备返回 `0x00000000`（关闭）或 `0x00000001`（不支持）则静默退出音频协程而不影响视频。
2. **12 字节包头**：
   - **Session 包**（`byte[0] & 0x80 != 0`）：`client_resized = (byte[3] & 1) != 0`、`width = BE u32(4..8)`、`height = BE u32(8..12)`。
   - **Media 包**（`byte[0] & 0x80 == 0`）：`is_config`（第 62 位）、`is_keyframe`（第 61 位）、`pts_us`（低 61 位）、`size = BE u32(8..12)`。客户端自动缓存最近的配置包（CSD）并在关键帧前补齐，录屏开启时同步写入 `MP4Recorder`。
3. **交互控制、无边框应用窗口与启动参数规则**：
   - 严禁在 `com.genymobile.scrcpy.Server` 启动命令行传递 `start_app` 或 `mouse=uhid`，也不得同时指定 `display_id` 与 `new_display`。
   - 独立 APP 窗口默认以 16 像素对齐的 `640x1120/220`（缩放时按 `1.5×` 像素倍率请求，但不超过链路的尺寸上限：中继链路 `960` 像素、较慢的直连组网 `1080` 像素）、`flex_display=true`、`vd_system_decorations=false` 与 `TYPE_START_APP`（`+pkg`）启动，剥离 Android 状态栏、导航栏与壁纸装饰，并绑定仅作用于该虚拟屏的 `AppGuard` 息屏保活（仅当虚拟屏有独立 `DisplayGroup` 时手机物理屏才保持熄灭）与「有限返回」（仅保留返回按钮与右键/`KEYCODE_BACK`，隐藏主页、最近任务与旋转按钮）。
   - 桌面交互按窗口级别隔离路由（`INV-12`）：通过 `TYPE_INJECT_TOUCH_EVENT`（`2`，支持 `PointerIDMouse = -1` 与 `PointerIDGenericFinger = -2`）、`TYPE_INJECT_SCROLL_EVENT`（`3`，`i16` 定点数）、`TYPE_INJECT_KEYCODE`（`0`）、`TYPE_INJECT_TEXT`（`1`）、`TYPE_SET_CLIPBOARD`（`9`，配合设备→电脑剪贴板回传）、`TYPE_SET_DISPLAY_POWER`（`10`）、`TYPE_ROTATE_DEVICE`（`11`）、`TYPE_UHID_*`（`12–14`）、`TYPE_START_APP`（`16`）与 `TYPE_RESIZE_DISPLAY`（`21`）发送。

## 2. Samsung Native DeX 本地回环、应用图标提取与 AppGuard（`server/dexhelper`）

`tools/builddex` 将 `server/dexhelper/src/com/androfuse/dexhelper/*.java` 编译打包为 `build/androfuse-dex-helper.jar`（`--min-api 30`，零 Root，UID 2000 `shell`）。

- **`probe`**：初始化 `Looper` 与 `ActivityThread`（`com.android.shell`）兼容壳，反射检测 `SemWifiDisplayConfig$Builder` 与 `IDisplayManager.connectWifiDisplayWithConfig`，输出 `AFDEX1|PROBE|{json}`。
- **`apps [--no-icons] [--skip-icons <csv>] [--resume <package>]`**：通过 `ActivityThread.systemMain()` 获取系统上下文，调用 `PackageManager` 查询 `ACTION_MAIN` / `CATEGORY_LAUNCHER`，过滤 WebAPK/十六进制哈希噪声包名，提取本地化应用名与 `resizeMode` 并渲染 `96x96` ARGB_8888 PNG 图标（传入 `--skip-icons` 时跳过电脑端已缓存图标的包名），逐行输出 `AFDEX1|APP|{json}` 与 `AFDEX1|APPS_DONE|<count>`。图标先取应用自身的图标资源，之后才用 `PackageManager.loadIcon`，因为在 One UI 上 `loadIcon` 会运行应用的「动态图标」代码（日历、时钟），在 shell uid 下会失败或让 `app_process` 在原生层中止。助手在绘制每个图标前输出 `AFDEX1|ICON|<package>`；若进程在此退出，电脑或守护进程保留已得到的应用并运行 `apps --resume <package>`（最多三次），该应用不带图标列出，然后继续其后的应用。在 Galaxy Z Fold8（One UI 9）上，全部 158 个应用连同图标在 1.9 秒内返回。
- **`appguard <display_id> <package>`（`AppGuard.java`）**：在 UID 2000 零 Root 权限下守护虚拟屏（`display_id > 0`）：持有一份 `PARTIAL_WAKE_LOCK` 与绑定该虚拟屏的 `SCREEN_BRIGHT_WAKE_LOCK | ACQUIRE_CAUSES_WAKEUP`（`PowerManager.newWakeLock(int, String, int)`）并刷新 `IPowerManager.userActivity(displayId, ...)`；注册 `DisplayManager.DisplayListener`，在物理主屏 `Display 0` 熄屏后唤醒虚拟屏（`cmd power wakeup --display-id <id> --restore-wakelocks`）——若虚拟屏位于独立 `DisplayGroup`（`> 0`）则仅唤醒该电源组而保持 `Display 0` 熄灭；若厂商系统将 `new_display` 放入 `DisplayGroup 0`（Galaxy Z Fold8，Android 17 上的 One UI），手机自身屏幕与它共用电源组，窗口打开期间保持亮起：关闭其面板电源（`SurfaceControl.setDisplayPowerMode(POWER_MODE_OFF)`，0.2.3 的做法）会让 Android 一并停止绘制虚拟屏，窗口因而冻结，直到手机屏幕重新点亮（已在 Galaxy Z Fold8 上确认）。若打开窗口时手机处于休眠、关闭时仍处于锁屏，AppGuard 会让手机重新休眠（`PowerManager.goToSleep`）；同时实现双层「有限返回」（检查 `IActivityTaskManager.getAllRootTaskInfosOnDisplay` 与 `dumpsys window windows` 的 `mOnBackInvokedCallbackInfo` / 输入法 / 浮窗，位于主页面时直接拦截返回避免黑屏，并由 `ITaskStackListener` 兜底保活）。
- **`serve <token> <w> <h> <dpi> <grace_sec>`**：先通过 `KEYCODE_WAKEUP` 唤醒息屏设备，持有 `/data/local/tmp/androfuse-dex.lock` 后调用 `disconnectWifiDisplay()`，绑定本地 UDP 排空端口与本地控制监听端口（`127.0.0.1:<ctrlPort>`，作为 `AFDEX1|<token>|READY|<id>|<w>|<h>|<dpi>|<type>|<flags>|<pid>|<ctrlPort>` 的第 8 字段返回），并调用 `connectWifiDisplayWithConfig`（`127.0.0.1:7236`、`"AndroFuseDeX"`、`mode=2`）完成 WFD RTSP 状态机并遵循**初始 DPI ≥ 160 引导规则**；支持运行期 `RESIZE <w> <h> <dpi>`，在 stdin 意外断开时进入 `grace_sec` 宽限保活窗口（输出 `AFDEX1|<token>|GRACE|<grace_sec>`），并在收到 `STOP` 或宽限到期后完整清理。PC 以脱离会话方式启动 `serve`（`setsid -w nohup`；toybox 不支持 `setsid -w` 时退回普通启动）：传输断开（USB 拔线、Wi-Fi 中断）时 adbd 会结束 shell 所在进程组，此前助手因此在宽限期开始前即被终止。
- **`attach <token> <ctrl_port>`**：在 USB→TLS Wi-Fi 热切换期间（`INV-02`）连接仍在存活的 `127.0.0.1:<ctrl_port>`，发送 `AUTH <token>` 鉴权后接收 `AFDEX1|<token>|REATTACHED|<id>|<w>|<h>|<dpi>`，无缝接管后续 `PING` / `RESIZE` / `STOP` 指令。
- **`SelectRoute` 与 `EvaluateTruth`（`INV-06`）**：One UI 9.0（`SDK 37`）将 DeX 合并进 SystemUI/Launcher（无独立 `com.sec.android.app.desktoplauncher` 包），因此 `internal/dex` 通过三星厂商身份、活跃 `SemWifiDisplayConfig` 与显示属性进行真伪判定与自动选路，并支持在“原生 DeX”与明确标注的“虚拟桌面兼容模式”间手动切换。

## 3. Miracast / Wi-Fi Direct 接收端（`core/androfuse-core/src/miracast.rs` — 已隐藏搁置）

- **全平台隐藏原因**：Windows 第三方应用无法仅凭公开 WinRT API 充当 Miracast 接收端，必须调用微软未公开的私有接口 `wlanapi.dll!WlanNotifyVsIeProviderInt`（`GUID b7d94b4d-5db1-4e70-b5c3-dd003eeebe66`）。在 Windows 11 ARM64（`build 26300`，高通 WCN685x WiFiCx 驱动 `qcwlan8280.sys` `1.0.4122.4000`）真机复测证实，外部手机对注入 `WlanNotifyVsIeProviderInt` 的 Wi-Fi Direct GO 接收端发起 Miracast 关联时，会直接触发 `qcwlan8280.sys` 内核工作线程访问违例蓝屏（`BugCheck 0x0000007E`，`0xC0000005`）。鉴于依赖未公开系统内部接口不具备稳定性保障，Miracast 方案已在全部平台界面中隐藏并在运行期禁用；有线 USB ADB 与 **加密 TLS 无线 ADB（`_adb-tls-connect._tcp`）** 作为正式支持的 DeX 双通道。
- **保留的纯协议离线单测**：`miracast.rs` 中的纯 Rust WFD RTSP 状态机、RTP 乱序重排、MPEG-TS H.264 解复用与 UIBC 报文编解码仍保留离线单元测试作为技术归档，不触碰任何无线网卡驱动。

## 6. 可选 Android Companion TLS 1.3 协同协议（`internal/companion`）

- **认证加密通道（`INV-07`）**：`internal/androidhost` 托管可选 ECDSA P-256 TLS 1.3 服务，共两个监听：在所有网卡上监听 TCP，端口取由手机设备 ID 得出的 20000–48999 内四个端口中第一个空闲的（`companion.DevicePorts`，对 ID 做 SHA-256；`companion.PickDevicePort`，四个都被占用时才用随机空闲端口；保存在 `companion.json`，伴侣界面会显示），以及在 Linux/Android 上通过内核 `SO_PEERCRED` 限定仅 UID `0`、`2000` 或伴侣自身 UID 访问的抽象本地套接字 `@androfuse-companion`（经 `adb forward tcp:0 localabstract:androfuse-companion` 连接，无需固定端口）。证书仅生成一次并经 Android Keystore 密封保存（`identity.sealed`，`companion.MarshalIdentity`），指纹由调用方固定；服务端在鉴权前限制未认证并发数（`32`）与单帧上限（`8 KiB`）并按源 IP 对失败次数限流，经 160 位配对令牌常量时间校验（`subtle.ConstantTimeCompare`）通过后再放开至 `24 MiB`。
- **分级授权开关与异网 ADB 端口信标（`INV-09`、`INV-11`）**：`status.get`（关闭 `ADBBeacon` 时自动清零 `WirelessADBPort`、`WirelessADBPairPort` 与 `WifiIPv4`）、`apps.list` 与 `daemon.open`/`daemon.ctrl`（受 `ScreenShare` 开关门控）、`clipboard.set`、`notification.reply`、`app.continuity`、`file.push`（路径穿越拦截 + SHA-256 校验）、`display.guard` 与动态 `_adb-tls-connect._tcp` 端口信标均由手机伴侣端独立开关门控；卸载 Companion APK 时基础有线/无线投屏与 DeX 仍完全可用。
- **经 adb 或已加入组网首次配对（TLS 会话绑定 SAS 与三选一数字确认，`INV-09`）**：经 adb 或已加入的 EasyTier 组网（`PairMeshPhone`）配对时，`RequestPairingSAS` 通过 TLS 1.3 `ExportKeyingMaterial`（`DerivePairSAS`，绑定对端证书 DER）在两端独立导出 6 位确认码防止中间人双端欺骗，对 `ClientName` 过滤控制字符与换行注入（`SanitizeClientName`），并对连续失败实施冷却限流。伴侣只在**通过校验的本地套接字或回环连接**上接受 `pair.request`，发出不含确认码明文的 `IMPORTANCE_HIGH` 悬浮通知（`Power.showPairNotification`），并在界面展示随机乱序的三选一数字按钮（1 个真实确认码 + 2 个干扰码，`AnswerPairChoice`），确认后返回 160 位 `token`、证书指纹、设备身份与初始状态；桌面先记入 `mesh:<devID>`，连接 ADB 后无损合并进 `HardwareHash`。
- **组网交接（`mesh.join`，`INV-07`、`INV-08`）**：仅在电脑用户勾选加入且组网运行时发送 `{network_name, network_secret, peers, label}`（`label` 是电脑上为该网络显示的名称，手机同样显示；电脑未发送时保留手机原有名称，手机的网络编辑器也可修改）。若手机当前已加入另一名称的网络，远端 `mesh.join` 会拒绝静默覆盖切换，需由手机端用户主动退出原网络后才可切换。手机用 Android Keystore AES-GCM 密封保存密钥，无 TUN、无监听端口加入，可随时退出。
- **免 adb 重连与省电**：`pair.res` 带回伴侣的 TCP `port`、`model` 与 `mesh_host`；`auth.res` 携带 `mesh_host`、`device_name`、`manufacturer` 与 `brand`。桌面将指纹与 DPAPI 密封的 160 位令牌存入 `devices.json`，经 adb 本地套接字或 EasyTier 回环转发重连（`INV-07`）。
- **通过伴侣转发无线调试与配对端口（`tunnel.open`，`INV-07`）**：`tunnel.open {port}` 只接受手机已核实的无线调试连接端口（`_adb-tls-connect._tcp`）或活跃且未过期（`3 分钟` TTL）的无线配对端口（`_adb-tls-pairing._tcp`），并在转发前校验本机回环可达性（`companion.ServeTunnels`）。
- **无线调试端口自动发现，不必手填**：`Power.kt` 通过 Android NsdManager 同时发现 `_adb-tls-connect._tcp` 与 `_adb-tls-pairing._tcp`，核实本机地址后在 `status.get` 中上报 `wireless_adb_port` 与 `wireless_adb_pair_port`。
- **引导添加与高级手动回退（`wizard.go`）**：+ 添加手机弹窗依次引导 USB 数据线、同 Wi-Fi 免输 IP 六位配对码（`_adb-tls-pairing._tcp`）与跨网络一键配对；原始 IP/端口填写与 `adb.FindWirelessPort`（30000–60999）收纳在可折叠的高级选项中。

## 7. 默认关闭的可授权本地 MCP 控制接口（`internal/mcp`）

- **默认关闭与本机回环绑定（`INV-07`、`INV-08`）**：进程启动时默认关闭（`Enabled=false`）；用户仅在设置页主动开启后才监听 `127.0.0.1:0` HTTP（`POST`），生成 30 分钟有效期随机 Bearer 令牌并通过常量时间校验（`subtle.ConstantTimeCompare`）。
- **白名单门控、紧急停止与脱敏审计**：`tools/list` 与 `tools/call` 严格遵循按工具 `Allowlist` 开关（启用时默认开放只读的 `list_devices` 与 `run_diagnostics`，`launch_app` 需单独授权）。`EmergencyStop()`（应用退出时自动调用）立即吊销密钥并关闭端口；审计日志永不记录令牌或原始设备序列号。 自 V3 起桌面端还会提供 `Handlers.Approve`：`tools/list` 因而列出全部工具，白名单只表示无需询问即可运行的工具（设置 › 安全与隐私），其余每次调用都会在窗格上方显示卡片（并发出通知），最多等待两分钟让用户选择「允许一次」或「拒绝」；结果写入审计（`approval`、`user_allowed_once` 或 `user_denied`）。

## 8. 双向摄像头与麦克风桥接协议（`internal/avbridge`，`M5`）

- **手机摄像头 + 麦克风回传**：`internal/scrcpy` 支持 `video_source=camera`（`camera_facing`、`camera_size`、`camera_fps`，强制 `control=false`）与 `audio_source=mic` 直采进入桌面 `SessionWindow` 及仅绑定 `127.0.0.1` 的随机路径令牌 MJPEG 服务（`avbridge.MJPEGServer`，无本地订阅客户端时零编码开销）；同时通过 `ProbeVirtualCamera` 诚实探测系统 `MFCreateVirtualCamera` 接口并明确提示未安装独立 COM 虚拟摄像头驱动。摄像头启动立即失败时会再尝试两次、间隔 1.5 秒，因为刚结束另一个摄像头会话时手机可能仍占用摄像头，其 scrcpy-server 会因此中止。摄像头窗格打开时为静音（手机麦克风在电脑扬声器上很响），标题栏提供「切换前后摄像头」、声音开关、截图与全屏，而不是手机按键；scrcpy 在启动时选定摄像头，因此「切换前后摄像头」保留同一个窗格或窗口、声音设置与 MJPEG 桥，在最后一帧上显示「正在切换到前置摄像头…」，关闭视频流（释放摄像头）后把另一个摄像头接入同一会话（`startCameraStream`）。
- **非 Root 下 PC→Android 回传（`INV-09`）**：`internal/companion` 的 `av.push` 帧在 TLS 1.3 加密隧道上传输有界（`<= 2 MiB`）的 `mic_pcm` / `camera_jpeg` 媒体帧，严格受手机 Companion 端默认关闭的 `MediaBridge` 开关门控。
- **UID 2000 常驻守护进程本机 IPC 与媒体流（`daemon.open` / `apps.list`）**：`dex.StartDaemon` 以 `chmod 600` 推送 `androfuse-dex-helper.jar` 与 `androfuse-scrcpy-server.jar`（本地缺少副本即报错），并在 UID 2000（`shell`）下脱离会话启动 `server/dexhelper` 的 `daemon` 子命令。只有 `StartDaemon` 写这两个文件：一次性 ADB 辅助命令（`probe`、`apps`、`serve`、`attach`、`recover`、`appguard`）从 `/data/local/tmp/androfuse-dex-tool.jar` 运行。由于守护进程启动时锁定两份摘要，每当手机经 adb 上线且 `dex.DaemonOutdated` 发现任一副本缺失、与本机版本不同或在守护进程启动后被改写，桌面端都会重启它；手机可经 adb 连接时，若 `daemon.open` 因 scrcpy-server 崩溃或被拒（`exited prematurely`、`verification failed`、`JAR integrity mismatch`）失败，`dialDaemonStream` 会重启一次并重试；`Daemon.java` 在派生 `scrcpy-server` / `dexhelper` 子进程前核验属主 UID（`shell`/`root`）、拒绝全局可写权限并锁定 SHA-256 摘要。其持有 `/data/local/tmp/androfuse-daemon.lock`，经 `IActivityManager.getContentProviderExternal` + `IContentProvider.call("sendBinder")` 向 `com.yuanzhe.androfuse.daemon`（`AndroFuseDaemonProvider`）推送权限收敛的 `IBinder`（`com.androfuse.daemon.IDaemon`），强制执行内核级 `Binder.getCallingUid() == expectedAppUid` 校验，探测 `ADD_TRUSTED_DISPLAY`，验证 `Os.socketpair` `ParcelFileDescriptor` 零拷贝通道（`TX_ECHO_FD`），绑定双向 `linkToDeath` 清理，并在 `status.get` 中上报 `daemon_ready`、`daemon_pid`、`daemon_trusted_display` 与 `daemon_fd_verified`。`apps.list`（`TX_LIST_APPS`）支持传入已缓存包名列表 `known_icons`，经 `Os.socketpair` `ParcelFileDescriptor` 流式返回含 `96x96` PNG 图标的完整 UTF-8 JSON 数组（绕开 Binder 1 MB 限制并保留 `--resume` 防崩恢复）。桌面端 `fetchApps` 会在超过四分之一的已缓存应用缺少图标时自动刷新（距上次尝试至少间隔 20 秒），并确保仅含包名的 adb 回退列表不会覆盖已缓存的应用名称与图标。在不开无线调试时，桌面端可通过 `daemon.open`（`DaemonStreamRequest`，含可选 `start_app`）与 `daemon.ctrl`（`companion.DialDaemonStream`，受 `ScreenShare` 开关门控、校验发起电脑令牌摘要，启用 `3s` TCP Keepalive 与 `TCP_NODELAY`）触发 `TX_OPEN_SESSION`，由守护进程拉起 `scrcpy-server v5.0.1`（采用 `cleanup=false` 保留服务端 JAR 供后续复用，同时靠进程退出与 Binder 死亡回收虚拟屏，`INV-03`），并在 `start_app` 会话上附加 `AppGuard` 与 `pumpCtrlForAppSession`（每当日志出现 `Video capture reset` 或转发 `TYPE_RESIZE_DISPLAY` 后，用 `cmd display power-off` / `power-reset` 重新给虚拟屏上电：在三星 One UI 上，若窗口打开时手机处于休眠，采集重置会让 SurfaceFlinger 中该显示停留在 `powerMode=OFF`，而显示服务仍认为它已开启，窗口因此不再绘制，直到手机锁屏再解锁；屏蔽主页键 `3` / 最近任务键 `187`、经 `AppGuard.shouldAllowBack()` 判定是否允许返回键 `4`，并在物理主屏熄灭时仅唤醒对应虚拟屏）；同时将视频 Socket 收发缓冲限制在 `64 KB`、管线拷贝缓冲限制在 `32 KB`（`tuneVideoConn`）。
